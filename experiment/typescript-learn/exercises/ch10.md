## Cách làm bài

**Không cần cài đặt:** dán code vào [TypeScript Playground](https://www.typescriptlang.org/play) (đã bật `strict`). Di chuột lên biến để xem kiểu được suy ra.

**Làm trên máy** (Node.js 18+):

```bash
mkdir generics-practice && cd generics-practice
npm init -y
npm install --save-dev typescript
npx tsc --init --strict --target es2022 --lib es2022,dom --noEmit
```

Mỗi bài một file (`bai01.ts`, `bai02.ts`...), thêm `export {};` ở đầu mỗi file để không đụng tên nhau. Kiểm tra bằng `npx tsc` hoặc `npx tsc --watch`.

**Tự chấm:**

- Lời giải đúng khi `tsc` không báo lỗi nào với các dòng kiểm tra trong đề.
- `// @ts-expect-error` nghĩa là dòng ngay dưới **phải** lỗi. Nếu lời giải quá lỏng, TypeScript báo *Unused '@ts-expect-error' directive*.
- Không dùng `any`. Không dùng `as` (trừ một chỗ được phép ở bài 10).

## Đề bài

### Bài 1 — Phần tử đầu tiên có giá trị mặc định

★ · Hàm generic, Golden Rule

Trang danh sách khách hàng cần hiện khách đầu tiên; nếu danh sách rỗng thì hiện giá trị mặc định. Viết lại hàm dưới đây bằng generic để kiểu trả về khớp kiểu phần tử, và **không cho** fallback khác kiểu với mảng.

```ts
function firstOrDefault(items: any[], fallback: any): any {
  return items.length > 0 ? items[0] : fallback;
}

const u = firstOrDefault(["an", "binh"], "khach"); // phải là string
const n = firstOrDefault([3, 5], 0);                // phải là number
// @ts-expect-error
firstOrDefault([1, 2, 3], "none");
```

Câu hỏi thêm: đồng nghiệp viết hàm dưới đây. Có cần generic không? Vì sao?

```ts
function printId<Id extends string | number>(id: Id): void {
  console.log(id);
}
```

### Bài 2 — Ghép hai danh sách thành cặp

★ · Nhiều type parameter

API trả tên sản phẩm và giá ở hai mảng riêng. Viết `zip(as, bs)` trả về mảng các tuple `[a, b]`, độ dài bằng mảng ngắn hơn. Dùng **hai** type parameter.

```ts
const names = ["Áo", "Quần"];
const prices = [250000, 400000];
const rows = zip(names, prices);
const r0: [string, number] = rows[0]; // phải OK
// @ts-expect-error
const bad: [number, string] = rows[0];
```

Câu hỏi thêm: gọi `zip<string>(names, prices)` thì có chuyện gì?

### Bài 3 — Bọc handler sự kiện

★★ · Type argument tường minh

Hàm sau bọc handler để ghi log mọi sự kiện:

```ts
function createEventHandler<Payload>(handler: (payload: Payload) => void) {
  return (payload: Payload) => {
    console.log("[event]", payload);
    handler(payload);
  };
}

interface CartItem { sku: string; quantity: number }

const onAddToCart = createEventHandler((item) => {
  console.log(item.sku, item.quantity); // lỗi ở đây
});
```

1. Vì sao `item.sku` báo lỗi? `item` đang có kiểu gì?
2. Sửa **chỉ bằng cách thêm type argument** khi gọi (không chú thích kiểu cho `item`).
3. Sau khi sửa, `onAddToCart({ sku: "A1" })` phải báo lỗi. Vì sao?

### Bài 4 — Kiểu cho response API

★ · Generic interface

Mọi endpoint của backend trả về cùng một vỏ: `data`, `status` (số), `fetchedAt` (Date). Endpoint danh sách thì `data` là một trang gồm `items`, `page`, `totalPages`.

1. Khai báo `interface ApiResponse<Data>` và `interface Paginated<Item>`.
2. Khai báo biến `pageRes` có kiểu "response chứa một trang `User`" bằng cách lồng hai interface.
3. Vì sao `const x: ApiResponse = ...` bị lỗi? Sửa interface thế nào để dòng đó hợp lệ?

```ts
interface User { id: number; name: string }

const firstName: string = pageRes.data.items[0].name; // phải OK
// @ts-expect-error
const wrong: ApiResponse<User> = { data: { id: "1", name: "Lan" }, status: 200, fetchedAt: new Date() };
```

### Bài 5 — Cache có kiểu

★★ · Generic class

Viết `class TypedCache<Key, Value>` bọc một `Map`, gồm:

- `set(key, value)`
- `get(key)` — trả về `Value | undefined`
- `getOrSet(key, factory)` — chưa có thì gọi `factory()` để tạo, lưu lại rồi trả về. Kiểu trả về là `Value` (không có `undefined`).

```ts
const userCache = new TypedCache<number, User>();
userCache.set(1, { id: 1, name: "Lan" });
// @ts-expect-error  (có thể undefined)
userCache.get(1).name;
const sure = userCache.getOrSet(2, () => ({ id: 2, name: "Minh" }));
sure.name; // phải OK
// @ts-expect-error
userCache.set("1", { id: 1, name: "Lan" });
```

Câu hỏi thêm: `new TypedCache()` (không truyền gì) có kiểu gì? Vì sao?

### Bài 6 — Kho hàng

★★ · Kế thừa class generic, method generic, static

```ts
interface Product { sku: string; name: string; stock: number }
```

1. Viết `class Inventory<Item>`: constructor nhận `Item[]`, method `add(item)`, và method generic `map<Result>(fn)` trả về `Result[]`.
2. Thêm `static of(...items)` tạo `Inventory` mới từ danh sách tham số. Thử dùng `Item` trong method static — đọc lỗi và giải thích.
3. Viết `class ProductInventory` kế thừa `Inventory` cho `Product`, thêm `lowStock(threshold)` trả về sản phẩm có `stock < threshold`.

```ts
const inv = new ProductInventory([{ sku: "A1", name: "Áo", stock: 3 }]);
const skus: string[] = inv.map((p) => p.sku);
const stocks: number[] = inv.map((p) => p.stock);
const tags: Inventory<string> = Inventory.of("sale", "new");
// @ts-expect-error
inv.add({ sku: "B2", name: "Quần" });
```

### Bài 7 — Kiểu Result

★★ · Generic type alias, discriminated union, default type parameter

Mở rộng ví dụ `Result` trong sách: cho phép chọn kiểu lỗi, mặc định là `Error`.

1. Khai báo `type Result<Data, Failure = Error>` là discriminated union theo trường `succeeded`.
2. Viết hai hàm tiện ích `ok(data)` và `fail(error)`.
3. Viết `parseAge(input: string): Result<number, string>` — lỗi khi không phải số nguyên hoặc ngoài khoảng 0–150.

```ts
const res = parseAge("27");
if (res.succeeded) {
  const a: number = res.data;   // OK
} else {
  const e: string = res.error;  // OK
}
// @ts-expect-error  (chưa thu hẹp)
res.data;
const d1: Result<number> = { succeeded: false, error: new Error("x") }; // OK nhờ default
// @ts-expect-error
const d2: Result<number> = { succeeded: false, error: "x" };
```

Câu hỏi thêm: nếu khai báo `type Result<Failure = Error, Data> = ...` thì sao?

### Bài 8 — Sắp xếp và đọc cấu hình

★★★ · Constraint (`extends`), `keyof`

```ts
interface AppConfig {
  apiUrl: string;
  timeoutMs: number;
  features: { darkMode: boolean };
}
interface SignupForm { email: string; age: number; acceptTerms: boolean }
```

1. Viết `sortById(items)` sắp xếp (không sửa mảng gốc) mọi object có `id: number` và **giữ nguyên** các trường khác trong kiểu trả về.
2. Viết `getSetting(config, key)`: `"apiUrl"` cho kiểu `string`, `"timeoutMs"` cho `number`, `"retries"` báo lỗi.
3. Viết `updateField(form, key, value)` trả về object mới; `value` phải khớp kiểu của trường `key`.

```ts
const sorted = sortById([{ id: 2, name: "B" }, { id: 1, name: "A" }]);
const nm: string = sorted[0].name; // phải OK
// @ts-expect-error
sortById([{ name: "A" }]);

const url: string = getSetting(config, "apiUrl");
const timeout: number = getSetting(config, "timeoutMs");
// @ts-expect-error
getSetting(config, "retries");

updateField(form, "age", 21);      // OK
// @ts-expect-error
updateField(form, "age", "21");
// @ts-expect-error
updateField(form, "phone", "090");
```

Câu hỏi thêm: vì sao không viết đơn giản `sortById(items: { id: number }[])`? Và nếu `getSetting` chỉ có một type parameter, `getSetting<Config>(source: Config, key: keyof Config)`, kiểu trả về là gì?

### Bài 9 — Timeout và bắt lỗi bất đồng bộ

★★ · `Promise<T>`, hàm `async`

1. Viết `delay(ms, value)` trả về Promise resolve `value` sau `ms` mili-giây (dùng để giả lập API chậm).
2. Viết `withTimeout(promise, ms)`: nếu `promise` xong trước `ms` thì trả kết quả của nó, ngược lại reject `Error("Quá thời gian ...")`. Kiểu kết quả giữ nguyên kiểu promise gốc.
3. Viết `async function tryAsync(task)` không bao giờ ném lỗi, luôn trả về `Result<T>` (bài 7).

```ts
const lengthLater: Promise<number> = delay(100, "xin chào").then((text) => text.length);
const guarded: Promise<number[]> = withTimeout(delay(50, [1, 2, 3]), 1000);

async function demo() {
  const result = await tryAsync(() => withTimeout(delay(10, 42), 100));
  if (result.succeeded) {
    const n: number = result.data;
  } else {
    const m: string = result.error.message;
  }
}
```

Câu hỏi thêm:

- `new Promise((resolve) => setTimeout(() => resolve("Done"), 100))` có kiểu gì? Sửa thế nào để thành `Promise<string>`?
- Vì sao `async function loadName(): string { return "Lan"; }` bị lỗi?

### Bài 10 — Mini API client

★★★ · Tổng hợp

Viết một client gọi API mà TypeScript **tự biết** kiểu dữ liệu của từng endpoint chỉ từ chuỗi đường dẫn. Code khởi đầu:

```ts
interface User { id: number; name: string }
interface Product { sku: string; price: number }

// Bản đồ: đường dẫn → kiểu dữ liệu trả về
interface ShopRoutes {
  "/users": User[];
  "/products": Product[];
  "/me": User;
}

type Fetcher = (path: string) => Promise<unknown>;

const fakeDb: Record<string, unknown> = {
  "/users": [{ id: 1, name: "Lan" }],
  "/products": [{ sku: "A1", price: 250000 }],
  "/me": { id: 1, name: "Lan" },
};
const fakeFetcher: Fetcher = async (path) => {
  await new Promise((r) => setTimeout(r, 10));
  if (!(path in fakeDb)) throw new Error(`404 ${path}`);
  return fakeDb[path];
};
```

Yêu cầu:

1. Viết `class ApiClient<Routes>` nhận một `Fetcher` qua constructor.
2. Method `get(path)` chỉ chấp nhận key của `Routes`, trả về `Promise<Result<Routes[Path]>>` (bài 7), không ném lỗi ra ngoài.
3. Dùng `TypedCache` (bài 5) để lần gọi thứ hai cùng đường dẫn không gọi `fetcher` nữa.
4. Vì `fetcher` trả về `unknown`, bài này cho phép dùng `as` để chuyển sang `Routes[Path]`. Giải thích vì sao chỗ đó không an toàn tuyệt đối.

```ts
async function main() {
  const api = new ApiClient<ShopRoutes>(fakeFetcher);

  const users = await api.get("/users");
  if (users.succeeded) {
    const names: string[] = users.data.map((u) => u.name); // OK
  }

  const me = await api.get("/me");
  if (me.succeeded) {
    const n: string = me.data.name; // OK
    // @ts-expect-error  (/me trả về một User, không phải mảng)
    me.data.map;
  }

  // @ts-expect-error  (endpoint không tồn tại)
  await api.get("/orders");
}
main();
```

Thử thách thêm: viết `getMany(...paths)` gọi song song nhiều endpoint, kiểu trả về là tuple khớp thứ tự — `getMany("/me", "/products")` có kiểu `[Result<User>, Result<Product[]>]`.

## Đáp án

Làm xong hãy đọc phần này. Lời giải của bạn khác đáp án vẫn có thể đúng — miễn là qua hết các dòng kiểm tra.

### Đáp án 1

```ts
function firstOrDefault<T>(items: T[], fallback: T): T {
  return items.length > 0 ? items[0] : fallback;
}
```

`items` và `fallback` dùng **chung** `T`, nên TypeScript buộc hai kiểu khớp nhau — đây chính là "mối quan hệ giữa các kiểu" mà generic mô tả.

`printId` **không cần** generic: `Id` chỉ xuất hiện một lần nên không nối kiểu nào với kiểu nào (vi phạm Golden Rule). Viết lại: `function printId(id: string | number): void`.

### Đáp án 2

```ts
function zip<A, B>(as: A[], bs: B[]): [A, B][] {
  const length = Math.min(as.length, bs.length);
  const result: [A, B][] = [];
  for (let i = 0; i < length; i++) result.push([as[i], bs[i]]);
  return result;
}
```

`zip<string>(names, prices)` lỗi *Expected 2 type arguments, but got 1*. Hàm có nhiều type parameter thì phải truyền tường minh **tất cả hoặc không cái nào**.

### Đáp án 3

1. `Payload` chỉ suy ra được từ kiểu tham số của callback. Callback `(item) => ...` không chú thích kiểu nên TypeScript không có thông tin và mặc định `Payload = unknown`. Truy cập `.sku` trên `unknown` là lỗi.
2. Sửa:

```ts
const onAddToCart = createEventHandler<CartItem>((item) => {
  console.log(item.sku, item.quantity); // item: CartItem
});
```

3. `onAddToCart` có kiểu `(payload: CartItem) => void`; object thiếu `quantity` không gán được cho `CartItem`.

### Đáp án 4

```ts
interface ApiResponse<Data> {
  data: Data;
  status: number;
  fetchedAt: Date;
}
interface Paginated<Item> {
  items: Item[];
  page: number;
  totalPages: number;
}

const pageRes: ApiResponse<Paginated<User>> = {
  data: { items: [{ id: 1, name: "Lan" }], page: 1, totalPages: 3 },
  status: 200,
  fetchedAt: new Date(),
};
```

`ApiResponse` không có default cho `Data`, nên mọi chú thích kiểu dùng nó phải kèm type argument (*Generic type 'ApiResponse<Data>' requires 1 type argument(s)*). Muốn bỏ được thì khai báo `interface ApiResponse<Data = unknown>`.

### Đáp án 5

```ts
class TypedCache<Key, Value> {
  #store = new Map<Key, Value>();

  set(key: Key, value: Value): void {
    this.#store.set(key, value);
  }
  get(key: Key): Value | undefined {
    return this.#store.get(key);
  }
  getOrSet(key: Key, factory: () => Value): Value {
    const existing = this.#store.get(key);
    if (existing !== undefined) return existing;
    const created = factory();
    this.#store.set(key, created);
    return created;
  }
}
```

`new TypedCache()` có kiểu `TypedCache<unknown, unknown>`: constructor không nhận tham số nào chứa `Key` hay `Value`, nên TypeScript không suy ra được và mặc định `unknown`. Với class kiểu này luôn truyền type argument khi `new`.

### Đáp án 6

```ts
class Inventory<Item> {
  protected items: Item[];

  constructor(items: Item[]) {
    this.items = items;
  }
  add(item: Item): void {
    this.items.push(item);
  }
  map<Result>(fn: (item: Item) => Result): Result[] {
    return this.items.map(fn);
  }
  static of<Element>(...items: Element[]): Inventory<Element> {
    return new Inventory(items);
  }
}

class ProductInventory extends Inventory<Product> {
  lowStock(threshold: number): Product[] {
    return this.items.filter((p) => p.stock < threshold);
  }
}
```

- `map` có type parameter riêng `Result`, mỗi lần gọi có thể khác nhau, độc lập với `Item` của instance.
- Dùng `Item` trong `static` lỗi *Static members cannot reference class type parameters*: static thuộc về class, không gắn với instance nào nên không có `Item` cụ thể. Vì vậy `of` khai báo type parameter riêng (`Element`).
- `ProductInventory` phải ghi rõ `Inventory<Product>` — TypeScript không suy ra type argument cho class cha.

### Đáp án 7

```ts
type Result<Data, Failure = Error> =
  | { succeeded: true; data: Data }
  | { succeeded: false; error: Failure };

function ok<Data>(data: Data): Result<Data, never> {
  return { succeeded: true, data };
}
function fail<Failure>(error: Failure): Result<never, Failure> {
  return { succeeded: false, error };
}

function parseAge(input: string): Result<number, string> {
  const age = Number(input);
  if (!Number.isInteger(age)) return fail(`"${input}" không phải số nguyên`);
  if (age < 0 || age > 150) return fail("Tuổi ngoài khoảng 0–150");
  return ok(age);
}
```

- `ok` trả về `Result<Data, never>`: nhánh lỗi có kiểu `never` nên gán được vào `Result<Data, bất kỳ>`. Nếu `ok` trả về `Result<Data>` (lỗi là `Error`) thì `return ok(age)` trong `parseAge` sẽ lỗi, vì ở đây kiểu lỗi là `string`.
- `res.data` trước khi kiểm tra `succeeded` lỗi vì nhánh thất bại không có `data` — đó là lợi ích của discriminated union.
- `Result<Failure = Error, Data>` lỗi *Required type parameters may not follow optional type parameters*: type parameter có default phải đứng sau cùng.

### Đáp án 8

```ts
function sortById<T extends { id: number }>(items: T[]): T[] {
  return [...items].sort((x, y) => x.id - y.id);
}

function getSetting<Config, Key extends keyof Config>(source: Config, key: Key): Config[Key] {
  return source[key];
}

function updateField<Form, Key extends keyof Form>(form: Form, key: Key, value: Form[Key]): Form {
  return { ...form, [key]: value };
}
```

- Nếu viết `sortById(items: { id: number }[])`, kiểu trả về chỉ còn `{ id: number }` — mất `name`, nên `sorted[0].name` lỗi. Generic có constraint vừa **yêu cầu** có `id`, vừa **giữ nguyên** kiểu đầy đủ của phần tử.
- Bản một type parameter trả về `string | number | { darkMode: boolean }` — hợp của **mọi** giá trị, vì TypeScript không biết bạn truyền key nào. Cần type parameter `Key` riêng để mỗi lần gọi "nhớ" đúng key đó.

### Đáp án 9

```ts
function delay<T>(ms: number, value: T): Promise<T> {
  return new Promise<T>((resolve) => {
    setTimeout(() => resolve(value), ms);
  });
}

function withTimeout<T>(promise: Promise<T>, ms: number): Promise<T> {
  return new Promise<T>((resolve, reject) => {
    const timer = setTimeout(() => reject(new Error(`Quá thời gian ${ms}ms`)), ms);
    promise.then(
      (value) => {
        clearTimeout(timer);
        resolve(value);
      },
      (error: unknown) => {
        clearTimeout(timer);
        reject(error);
      },
    );
  });
}

async function tryAsync<T>(task: () => Promise<T>): Promise<Result<T>> {
  try {
    return { succeeded: true, data: await task() };
  } catch (error) {
    return {
      succeeded: false,
      error: error instanceof Error ? error : new Error(String(error)),
    };
  }
}
```

- `catch (error)` có kiểu `unknown` ở chế độ strict, nên phải kiểm tra `instanceof Error` trước khi đưa vào `Result`.
- `new Promise((resolve) => ...)` có kiểu `Promise<unknown>` vì constructor không suy ra được kiểu từ lời gọi `resolve` bên trong. Sửa: `new Promise<string>((resolve) => ...)`.
- `async function loadName(): string` lỗi *The return type of an async function or method must be the global Promise<T> type*. Sửa thành `Promise<string>`.

### Đáp án 10

```ts
class ApiClient<Routes> {
  #fetcher: Fetcher;
  #cache = new TypedCache<keyof Routes, unknown>();

  constructor(fetcher: Fetcher) {
    this.#fetcher = fetcher;
  }

  async get<Path extends keyof Routes & string>(path: Path): Promise<Result<Routes[Path]>> {
    const cached = this.#cache.get(path);
    if (cached !== undefined) {
      return { succeeded: true, data: cached as Routes[Path] };
    }
    try {
      const raw = await this.#fetcher(path);
      this.#cache.set(path, raw);
      return { succeeded: true, data: raw as Routes[Path] };
    } catch (error) {
      return {
        succeeded: false,
        error: error instanceof Error ? error : new Error(String(error)),
      };
    }
  }

  async getMany<Paths extends (keyof Routes & string)[]>(
    ...paths: Paths
  ): Promise<{ [Index in keyof Paths]: Result<Routes[Paths[Index]]> }> {
    return Promise.all(paths.map((p) => this.get(p))) as Promise<{
      [Index in keyof Paths]: Result<Routes[Paths[Index]]>;
    }>;
  }
}
```

- `Path extends keyof Routes` là kỹ thuật của bài 8 áp dụng cho method: mỗi lần gọi `get` "nhớ" đúng đường dẫn, nên `Routes[Path]` ra đúng kiểu dữ liệu.
- `& string` vì `keyof` có thể gồm cả `number` và `symbol`, còn `fetcher` chỉ nhận `string`.
- `as` không an toàn tuyệt đối: TypeScript chỉ tin bản đồ `ShopRoutes`, không kiểm tra JSON thật. Nếu backend đổi `name` thành `fullName`, code vẫn biên dịch nhưng chạy sai. Muốn an toàn thật cần validate lúc chạy (Zod, Valibot...).
- `getMany`: rest parameter generic khiến TypeScript suy `Paths` là tuple `["/me", "/products"]`; mapped type trên tuple giữ nguyên thứ tự khi chuyển từng phần tử thành `Result` (Chương 15 sẽ nói kỹ về mapped type).
